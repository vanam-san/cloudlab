# Caddy on VPS

[Caddy](https://caddyserver.com/docs/) reverse proxy with automatic HTTPS,
using the official `caddy:latest` image, deployed with Docker Compose.

Every site is gated by **HTTP Basic Auth by default** — the browser
prompts for a username/password before the request reaches the app
(which still has its own login behind it). This works from any browser
over HTTPS, no VPN required. **Tailscale stays available as an optional
extra layer** (`import tailscale-only`), but it's off unless you opt in.

Backend apps run in sibling compose projects (e.g. `../umami`) on
localhost-only port bindings and are reached from Caddy via those ports
(e.g. `reverse_proxy localhost:3000`).

## Quick start (one command)

Requires Docker + Docker Compose on the server. Ports 80 and 443 must be free.

```bash
./run.sh
```

That one command:

1. Creates `.env` from `.env.example` (if missing)
2. Creates `basic-auth.caddy` from its `.example` (if missing) with a
   **strong random password — printed once, store it now** (it's kept
   only as a bcrypt hash, in a git-ignored file)
3. Creates `tailscale-ips.caddy` from its `.example` (if missing) —
   only needed if you opt into Tailscale IP filtering
4. Pulls the latest Caddy image
5. Validates the Caddyfile
6. Starts Caddy and waits until healthy

## Adding a site

Point the domain's DNS at this server, edit `Caddyfile`:

```caddyfile
analytics.example.com {
	import basic-auth
	reverse_proxy localhost:3000
}
```

`import basic-auth` is the default gate: the browser must authenticate
(credentials in `basic-auth.caddy`, generated by `run.sh`). The app's own
login still applies after that. To also restrict a site to your tailnet,
add `import tailscale-only` on the next line (set your IPs in
`tailscale-ips.caddy` first). To make a site fully public, remove
`import basic-auth` — only do that for things meant to be public.

Then reload without downtime:

```bash
docker compose exec caddy caddy reload --config /etc/caddy/Caddyfile --adapter caddyfile
```

Caddy obtains and renews the TLS certificate automatically. Certificates
and config persist in the `caddy-data` / `caddy-config` Docker volumes.

## Managing Basic Auth users

Credentials live in `basic-auth.caddy` (git-ignored). To change the
password or add a user: generate a bcrypt hash, edit the file, reload:

```bash
docker run --rm -i caddy:latest caddy hash-password   # type password on stdin
docker compose exec caddy caddy reload --config /etc/caddy/Caddyfile --adapter caddyfile
```

Use a long random password — this is the only thing standing between the
internet and your apps' login pages (HTTPS is automatic; app logins still
apply behind it; Docker ports stay bound to localhost).

> **Naming rule:** the service you proxy must have a globally unique
> compose service name — it becomes DNS on the shared `cloudlab-proxy`
> network for every stack. Never use generic names (`web`, `api`, `db`);
> name it after the app (`sure`, not `web`) and keep the Caddy upstream
> on the container-internal port.

## Updating

Per upstream docs ([Install](https://caddyserver.com/docs/install),
Docker image):

```bash
./update.sh
```

It pulls the latest `caddy` image and recreates the container. Certs,
config and the Caddyfile are untouched (volumes + bind mount), so there
is no re-issuance and no downtime beyond the container restart.

## Common commands

```bash
./run.sh                                    # pull latest + (re)start
./update.sh                                 # update Caddy
docker compose logs -f caddy
docker compose exec caddy caddy reload --config /etc/caddy/Caddyfile --adapter caddyfile      # apply Caddyfile changes
docker compose down        # stop (keeps certificates)
docker compose down -v     # stop + delete certificates/config
```

## Using this folder as a template

This folder is self-contained: copy it out of this template repo to use
it on its own (or clone this repo with sparse-checkout). `.env`,
`basic-auth.caddy` and `tailscale-ips.caddy` are git-ignored; the
Caddyfile itself contains no secrets (`run.sh` generates the Basic Auth
password on first run).

```bash
cp -r caddy ~/my-caddy && cd ~/my-caddy
git init
git add .
git commit -m "Initial caddy setup"
git branch -M main
git remote add origin https://github.com/<you>/<repo>.git
git push -u origin main
```

On the VPS:

```bash
git clone https://github.com/<you>/<repo>.git
cd <repo>
./run.sh
```
